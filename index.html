Text File Processing

Variables disappear when a program ends. Files keep data on disk so it can be read again later, by the same program or another one. This chapter shows how Python finds a file, opens it, reads and writes it, closes it safely, and handles the errors that can happen along the way.

1 · Text files2 · File paths3 · os.path4 · Opening & modes5 · File objects6 · Reading7 · Writing8 · Closing9 · Exceptions10 · with11 · Rename, copy, move12 · Review
Daily-life picture: working with a file is like using a library book. You must know where it is (file path), borrow it (open), read or write in it, and return it (close). If something goes wrong (the book is missing), you need a plan B (exception handling).

1. Text files

A text file can be thought of as one long string stored on disk. A special character marks the end of each line. Operating systems use different end-of-line markers, but Python handles that for us and always uses the newline character \n.

What you see in Notepad

Hello
World

Goodbye 4ever!

What Python sees: one string

The empty line in the middle is just two \n in a row. The file ends with a \n too. This string is 28 characters long, and the reading demos below use exactly this file.

The basic workflow

  1. Open the file: connect a file on disk to a file object in the program.
  2. Read or write through that file object.
  3. Close the file when you no longer need it.

2. File paths

A file path tells the program where the file is. It is made of components separated by a special character: drive or root, then folders, and the file name last.

C:\Users\User\Desktop\testing.docx

drive folders file name (always last)

SystemSeparatorExample
Linux / macOS/ (forward slash)"/home/user/testing.docx"
Windows\ (backslash)C:\Users\User\Desktop\testing.docx

Writing a Windows path in Python

In a Python string, the backslash starts an escape sequence (\n = new line, \t = tab). So a Windows path needs special care. Two correct ways:

✔ Way 1: double every backslash
"C:\\Users\\User\\Desktop\\testing.docx"
✔ Way 2: raw string, r before the quote
r"C:\Users\User\Desktop\testing.docx"

Forward slashes also work on Windows: "C:/Users/User/Desktop/testing.docx".

Careful with slide 27: open('C:\Users\User\Desktop\testing.txt') does not even run. \U starts a Unicode escape, so Python gives SyntaxError: (unicode error) 'unicodeescape' codec can't decode bytes. Other paths fail silently instead: in "C:\new\test.txt", \n becomes a new line and \t a tab. Always use r"..." or \\.

path = os.path.abspath(filename)          # C:\Users\User\Python\Chapter 3\Testing.txt

5. File objects

  
open() returns a file object, also called a file handler. Through it you read, write, and check information about the file.

  

    
AttributeReturns

    
f.namethe file name, e.g. testing.txt

    
f.modethe mode it was opened with, e.g. r

    
f.closedTrue if the file is closed, otherwise False

  


f = open("testing.txt", "r")
print("File name is", f.name)      # File name is testing.txt
print("File state is", f.closed)   # File state is False
print("File mode is", f.mode)      # File mode is r
f.close()
print("File state is", f.closed)   # File state is True

  
These are attributes, not methods, so there are no brackets: f.closed, not f.closed().

Key idea: the file cursor. A file object remembers where it is. Each read moves the cursor forward, and the next read continues from there. When the cursor is at the end, reads return an empty string ''. seek(0) rewinds it.

Why do my lines print with blank lines between them?


f = open("testing.txt", "r")
for line in f:
    print(line.lower())        # each line already ends with \n, and print() adds another

  
Each line already ends with \n, and print() adds a second one. Fix it with print(line.rstrip("\n")), print(line.strip()) or print(line, end="").

  
On Windows: a new line is stored on disk as two bytes (\r\n), and tell() counts bytes. So on Windows, tell() after read(20) can be larger than 20. Python still gives you only \n when reading.

8. Closing a file

  
Always f.close() when you're finished:

  
    
    
  • Saves the data: written text may wait in a memory buffer; closing makes sure it really reaches the disk. Without it, the file may be empty or incomplete (data loss, corruption).
    • 
    
  • Frees resources: the operating system can only keep a limited number of files open.
    • 
    
  • If you forget, Python's garbage collector will close it eventually, but the file may stay open for a while.
    • 
  


f.close()
f.read()     # ValueError: I/O operation on closed file.


  
  
9. Handling file exceptions

  
File operations depend on things outside your program, so they often fail. They raise an IOError (in Python 3 this is the same as OSError), or a more specific subclass of it:

  

    
SituationException

    
open a file for reading that doesn't existFileNotFoundError

    
no permission to read, or writing in a protected folderPermissionError

    
create a file in a folder that doesn't existFileNotFoundError

    
disk or network error while accessing the fileOSError

    
write to a file opened with "r"io.UnsupportedOperation: not writable

    
use a file after close()ValueError: I/O operation on closed file

  

  
If an error happens after opening, the program jumps out and the file is never closed. try / except / finally fixes that:

  
  • try: the code that might fail.
  • except: runs if an error happens.
  • finally: always runs, the right place for close().

  
Slide 55 has a hidden bug:

try:
    f = open('testing.txt', 'r+')
except:
    print("Something went wrong while opening the file!")
finally:
    f.close()          # if open() failed, f was never created → NameError!

  If the file is missing, open() fails, so f doesn't exist, and finally crashes with NameError: name 'f' is not defined. That's why slide 56 uses a nested try: the outer one handles opening, the inner one handles reading/writing and closes the file only if it opened.


try:
    f = open('testing.txt', 'r')         # outer try: opening
    try:
        f.write("Testing file exceptions.")   # fails: the file was opened with 'r'
    except:
        print("Something went wrong while writing the file!")
    finally:
        f.close()                        # runs only if open() worked
except:
    print("Something went wrong while opening the file!")

  
Slide 56 prints "Something went wrong while writing the file!" because mode 'r' can't write. Slide 57 changes the mode to 'w', and the write succeeds.

  
Better practice: name the error, e.g. except FileNotFoundError:. A bare except: also hides your own typos.


  
  
10. The with statement (context manager)


with open('testing.txt', 'r') as f:
    for line in f:
        print(line.lower())
# here the file is ALREADY closed, even if an error happened inside the block

  
with creates a context manager that closes the file automatically when the block ends, even if an exception is raised. It is the cleanest and safest way to work with files.

  


Without with: 7 lines
f = open("data.txt", "r")
try:
    text = f.read()
finally:
    f.close()
print(text)


With with: 3 lines, same safety
with open("data.txt", "r") as f:
    text = f.read()
print(text)

  

  
with doesn't stop open() from failing, so a missing file still needs try/except FileNotFoundError around it.
